# Nudge for iOS

Two native SwiftUI apps in one Xcode project, sharing the API client and the sensor maths (`Shared/`):

| Target | Who | What |
|---|---|---|
| **Nudge** | the blind traveller | A hands-free tool. The phone rides **on their back** (back pocket, backpack pouch or harness, upright). It waits for a trip, calibrates with a spoken countdown, counts steps, works out walking direction, streams both to the Raspberry Pi, and speaks every instruction. The Pi's servo collar taps the shoulders. The traveller talks back: "where am I", "repeat", "how far", "I need help", "the door is locked", "yes" / "no", "stop". |
| **Nudge Care** | the caretaker | A polished app: pair with the traveller's 6-digit code, send a trip, watch a live status card and floor-plan map, follow a timeline, get a red alert plus notification when they need help. |

Position tracking is steps + compass (no ARKit). Both apps talk plain HTTP to the Nudge server on the Pi (`nudge/server.py`).

## Build it (on a Mac with Xcode 15 or later)

**Option A, recommended:** generate the project from `project.yml`.

```bash
brew install xcodegen
cd ios
xcodegen
open Nudge.xcodeproj
```

**Option B:** open the checked-in `ios/Nudge.xcodeproj` directly. It was generated by script, parses cleanly and has every file wired, but it has never been opened in Xcode. If Xcode complains, use Option A.

Then, for each app you install:

1. Select the target (**Nudge** or **NudgeCare**). Under **Signing & Capabilities**, pick your Apple ID team (a free personal team is fine). If the bundle id is taken, change `com.hackprinceton.nudge` / `com.hackprinceton.nudgecare` to something unique.
2. Plug in the iPhone and select it as the run destination.
3. On the iPhone, turn on **Settings → Privacy & Security → Developer Mode** (it restarts).
4. Press **Run**. The first time, trust the developer: **Settings → General → VPN & Device Management → your Apple ID → Trust**.
5. Allow Motion, Location, Microphone and Speech Recognition (Nudge) and Notifications (Nudge Care) when asked.

Unit tests (step detector, heading maths, step queue): select the **Nudge** scheme and press ⌘U on a simulator.

## Demo, end to end

The full Pi setup is in `docs/live-demo.md`. Short version:

1. **Network:** the traveller's iPhone shares its hotspot. The Pi and the caretaker's phone join it.
2. **On the Pi:** `sudo pigpiod`, then:
   ```bash
   OPENBLAS_NUM_THREADS=1 NUDGE_BAND=1 python -m uvicorn nudge.server:app --host 0.0.0.0 --port 8765
   ```
3. **Traveller phone, one-time setup** (a helper can do it, or the traveller with VoiceOver):
   - set the Pi address (usually `http://172.20.10.2:8765` to `…14:8765` on an iPhone hotspot) and tap Test;
   - choose how the phone is worn;
   - set the step length;
   - note the **6-digit caretaker code**.
   Then the screen goes dark and says "Waiting for a trip".
4. **Caretaker phone, Nudge Care:** in Settings, set the same Pi address. Enter the code. Tap **Send trip**, pick the building (Rabinowitz Hall) and the destination (Grand staircase, Seminar room), and send.
5. **Traveller:** the phone on their back says "Your caretaker sent a trip to the seminar room…", then "Stand at the entrance facing the way you'll walk. Calibrating in 3, 2, 1. Go ahead." They walk. Turns, doors and distances are spoken, and the collar taps.
6. **Caretaker:** watches the pulsing dot move on the floor plan, sees "Walking → Arrived", and gets a red alert if the traveller says "I need help".

Fallbacks: a double tap anywhere on the traveller's screen restarts the last trip. Saying "start my trip" does the same.

## How the back mount works

A compass heading from Core Location follows the phone's top edge, which points at the sky when the phone is upright on someone's back. Instead, `Motion.swift` reads device motion in a north-referenced frame (`.xTrueNorthZVertical`, else magnetic). It takes the screen axis, projects it onto the floor, and turns that into a heading clockwise from north. The setting decides which way is forward:

- **Screen faces my back:** the screen is against the body, so the screen normal points forward.
- **Screen faces out:** the screen faces away from the body, so forward is the opposite way.

If the phone lies flat there's no forward direction. The app then keeps the last heading and the status says the direction is unreliable.

**Check this on a real phone before the demo:** wear it, face a known direction, and compare the heading readout to a compass app. If it's off by 180°, flip the mount setting. The Core Motion rotation-matrix convention it relies on (`Heading.walking`) is unit-tested but has not been verified on a device.

## Staying alive with the screen locked

The traveller app uses a play-and-record audio session and the `audio` background mode, which needs no special entitlement. Speech and listening keep it running when the screen locks. While it's open it also disables auto-lock and stays black. Device motion keeps flowing as long as the app runs.
